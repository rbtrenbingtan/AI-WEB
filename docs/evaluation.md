# 评测与数据真实性

自动化工程测试验证接口约束、会话隔离、首答计分、补练与复测、句子引用、解析限制和生成质量门槛。测试替身只用于验证模型协议和错误处理，不能作为真实模型质量或时延结果。

示例讲义和题目由本次编码助手离线编写。自动规则可检查选项数量、引用归属、答案位置等结构属性，无法代替独立内容审定。未完成的人类审定、真实模型盲答、留出资料实验、用户测试不能填成已完成。

正式评测步骤：

1. 团队先审定示例讲义及误区，记录审定人、时间和改动。保留初稿与修订记录。
2. 开发集与冻结测试集分开；留出另一章节的 5—8 页授权讲义，不在开发时使用。
3. 给定同一模型、资料及知识点，分别运行「整章普通出题」基线与当前证据包工作流，每组至少 20 个候选。
4. 两人独立标注唯一正确、证据支持、误区归属，保留分歧，不把模型自审当作人工标注。
5. 使用 `scripts/export_metrics.py` 导出实际模型调用、题库和答题汇总。失败率分母包含失败与重试，成本按服务商实际价格另算。
6. 记录 3—5 名用户能否独立完成流程。样本不足以证明长期学习效果。

`eval/manual_review.csv` 是空白评分表，不能直接作为结果报告。每条证据存在且归属正确，也不意味着它在语义上支持答案。
